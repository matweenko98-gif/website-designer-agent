# Форма заявок: сайт → база → Telegram

Применять, когда на сайте есть форма заявки, записи или обратной связи. Стек — из `STACK.md`. Форма должна работать по-настоящему: каждая заявка сохраняется в базе и сразу приходит владельцу в Telegram.

## Как устроено

```
Посетитель заполняет форму
  → POST /api/lead (серверный обработчик сайта, app/api/lead/route.ts)
      → проверка данных и защита от спама
      → запись в Supabase (таблица leads)
      → сообщение владельцу в Telegram
  → форма показывает результат
```

Всё работает внутри сайта: отдельный сервер для бота не нужен. Локально (`npm run dev`) заявки идут с ноутбука, после публикации — с Vercel, круглосуточно. Отдельный постоянно запущенный бот нужен, только если он должен сам отвечать клиентам в Telegram (диалог, запись, оплата) — это следующий этап, не часть сайта; упомяни его в `content/after-launch.md`, если пользователь об этом говорил.

## Форма на странице

- Поля — минимум для связи: обычно имя и телефон (или Telegram), по смыслу проекта — комментарий или выбор услуги. Каждое лишнее поле снижает число заявок
- Подписи полей видны всегда (не только placeholder), телефон — `type="tel"` с `autocomplete`, понятная подсказка формата
- **Согласие на обработку персональных данных** — отдельный неотмеченный чекбокс со ссылкой на политику. По законам РБ и РФ это обязательно, когда сайт собирает имя и телефон. Если политики нет, сделай страницу-черновик с данными владельца из `PROJECT.md` и пометкой для пользователя «проверьте с юристом»; неизвестные реквизиты не выдумывай
- Скрытое поле-ловушка для ботов (honeypot): человек его не видит, бот заполняет — такие заявки молча отбрасываются
- Состояния: отправка (кнопка неактивна, видно, что идёт отправка), успех (что будет дальше: «Перезвоним в течение часа» — только если это подтверждённое обещание), ошибка (простыми словами и запасной способ связи: телефон или Telegram владельца)
- Вместе с заявкой сохраняй, откуда она пришла: адрес страницы и UTM-метки из ссылки, если есть

## Серверный обработчик `app/api/lead/route.ts`

- Проверяет данные на сервере, даже если форма проверила их в браузере: обязательные поля, длины, формат телефона, поле-ловушку, согласие
- Простое ограничение частоты отправок с одного адреса, чтобы форму не заваливали
- Пишет в Supabase через `@supabase/supabase-js` с **секретным ключом** — только на сервере
- Шлёт сообщение в Telegram запросом к `https://api.telegram.org/bot<токен>/sendMessage` с `chat_id` владельца. Текст — обычный, без `parse_mode` (иначе символы из заявки ломают разметку) или с экранированием
- Успех, если заявка сохранилась хотя бы в одном месте; сбой второго канала записывай в лог сервера. Ошибка для посетителя — только если не сработало ничего
- Ключи и токены не попадают в ответ, в лог и в код браузера

Переменные (в `site/.env.example` — названия с пустыми значениями и комментарием по-русски, откуда взять каждую):

```
SUPABASE_URL=
SUPABASE_SECRET_KEY=
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
```

У Supabase сейчас два вида ключей: новые `sb_publishable_…` (публичный) и `sb_secret_…` (секретный) и старые `anon` / `service_role`, которые Supabase выводит из употребления. Для сервера нужен секретный: `sb_secret_…`, а в старых проектах — `service_role`. Публичный ключ здесь не нужен: браузер в базу напрямую не пишет.

## База Supabase

Создай `supabase/leads.sql` в самом начале шага 4, до вёрстки, — чтобы пользователь выполнил его, пока ты собираешь сайт (`AGENTS.md`, «Ты ведёшь…»). Таблица и защита:

- таблица `leads`: `id` (uuid по умолчанию), `created_at` (время по умолчанию), `name`, `phone`, `message`, `page`, `utm` (jsonb), `consent` (boolean) и поля под проект; ограничения длины на текстовые поля
- `alter table leads enable row level security;` **без** открытых политик: читать и писать может только сервер с секретным ключом, никто снаружи

Пользователь выполняет файл сам: Supabase → проект → **SQL Editor** → вставить содержимое → **Run**. Объясни это шагами.

## Telegram-бот для уведомлений

Пользователь создаёт бота сам, ты ведёшь по шагам. Лучше всего — заранее, пока ты исследуешь (перед шагом 2); тогда на шаге 5 остаётся только `chat_id`:

1. В Telegram открыть [@BotFather](https://t.me/BotFather) → `/newbot` → придумать имя и адрес бота (должен заканчиваться на `bot`) → скопировать токен в `TELEGRAM_BOT_TOKEN` в `site/.env.local`
2. Открыть своего бота и нажать **Start** (или написать ему любое сообщение) — без этого бот не может писать первым
3. Узнать `chat_id`: сделай скрипт `npm run telegram:chat-id`, который берёт токен из `.env.local`, вызывает `getUpdates` и печатает найденные чаты с их `chat_id`. Пользователь запускает его (или ты) и вставляет число в `TELEGRAM_CHAT_ID`. Так токен не нужно открывать в браузере и присылать в чат. Для группы: добавить бота в группу, написать в ней сообщение, запустить скрипт; `chat_id` группы начинается с минуса

Сообщение о заявке — коротко и полезно: «Новая заявка с сайта», имя, телефон (кликабельный в Telegram), комментарий, услуга, страница и UTM, время по местному часовому поясу владельца.

## Проверка

1. Локально: `npm run dev`, отправить тестовую заявку → строка появилась в Supabase (**Table Editor → leads**), сообщение пришло в Telegram
2. Ошибки: пустые поля, неверный телефон, без согласия, заполненная ловушка — форма объясняет, что не так, мусор не сохраняется
3. После публикации: те же четыре переменные в Vercel → повторная публикация → тестовая заявка с телефона по публичной ссылке
4. Удалить тестовые заявки из таблицы или пометить их, если пользователь хочет чистую базу

Если ключей ещё нет, доделай всё остальное и честно скажи, что форма заработает после шагов пользователя. Не показывай «Заявка отправлена», если она никуда не ушла.
